# 自有视觉素材库、封面结尾与配音方案

## 这版素材的真实来源

参考视频用于分析风格、构图和讲解机制，未从中截取画面、图标、动画片段或音轨。图形是项目内 React/SVG 组件绘制的，工作台素材来自本项目真实浏览器操作；中文字体来自随项目分发并保留许可的 Noto 字体。没有使用参考片的人声音色来克隆配音。

此前介绍片是固定编排的工程自测：由作者选择画面、写 TSX 并用真实 Remotion 渲染，不是一次已经验收的原生模型自动创作。开头的过渡标题和结尾的验收页不能替代独立品牌封面与结束页；本次补充独立封面 3 秒、结束页 4 秒。

## 风格、元素和动效怎样设计

顺序是：确定观众要理解的结论 → 选一个可视化关系 → 定义对象及其状态 → 编排分镜 → 给动作选择旁白短语锚点 → 按实际音频时间戳编译到帧 → 渲染、观察和修正。模型可以选择库里的积木，也可以编写专用 TSX；没有把选型退化为关键词路由。

| 层次 | 本项目做法 | 举例 |
|---|---|---|
| 风格 | 固定颜色、字体层级、留白、边线、圆角与强调比例 | 暖白 `#f4efe5`、深青 `#273b38`、红色强调 `#a63d49` |
| 素材 | 可编辑源码、真实 UI、字体、项目数据 | SVG 图形、实际工作台录制、Noto 字体 |
| 元素 | 对象、连接、容器、队列、文本与代码 | 卡片、节点、连线、容量条、粒子、代码行 |
| 布局 | 把信息关系转换为几何关系 | 网格/扇形概览、并排对比、中心关系网络 |
| 状态 | 给每个对象定义初态与终态 | 未出现→出现，普通→强调，空队列→积累 |
| 动效 | 用帧驱动状态变化，按实际旁白定位 | reveal / highlight / progress，扫描线、路径绘制 |
| 镜头 | 服务于一个讲解目的的完整画面 | 品牌封面、机制解释、真实演示、价值收束 |

优秀参考片的优势还包括跨镜头对象延续、隐喻和节奏；基础组件本身不等于这些能力。图解的数量与标签长度有边界，超出时应拆镜头或编写专用组件。

## 第一版素材库已落地

目录是 `assets/library/catalog.json`，包含 15 项：2 套风格、7 类视觉表达、3 类动效、独立封面/结束页和中文字体。每项记录 ID、版本、解释目的、源代码入口、来源、使用条款、验证状态和实际源文件 SHA256。

- `GET /api/v1/material-library` 使用现有登录鉴权读取目录。
- 工作台“环境与能力”显示素材条目、用途及“已实现/未验证/受阻”状态。状态不等于人工审美或听感认证。
- 原生策划请求携带相同目录。选中的资产以 `library:<id>@<version>` 记录在分镜的 `assets` 中，拒绝不存在或受阻的条目，并记录目录修订指纹。
- 三类尚未单独形成视觉样例验收的表达保留“未验证”，不会因为源码存在就宣称参考片效果通过。
- 已有代码通过受保护的 `motion-kit.tsx` 复用；目录是描述与选择入口，不执行上传代码。

后续新增资产的流程：产生候选组件/图片/声音 → 记录来源与许可 → 编译和测试 → 生成真实预览 → 检查字幕、边界和运动 → 审阅后入库 → 发布新版本。资产 ID、版本、Git 提交、源文件指纹、预览证据与实际影片要能对应。

第二阶段再增加视觉缩略图浏览、上传/审批、图片和视频检索、音色预设、按旁白情绪选型、历史版本恢复及完整管理界面。目前落地的是可供 Agent 使用的版本目录与基础浏览入口。

## 声音为什么不够自然

实际音轨是 **Edge `zh-CN-YunxiNeural`**，没有使用 Qwen 或 Ming。原片提到“Qwen”是在引用架构文案，不能据此判断供应商。此次封面结尾修订保留原音轨，结束页明确标注 Edge；没有将它包装成 Ming 试听结果。

此前测量只证明音量、完整性和时间戳符合检查；用户反馈的自然度问题仍需处理。从脚本看，可能影响听感的因素包括：直接朗读 README、长句、连续英文技术名词和文件扩展名，以及分段生成后句间语气衔接不足。没有完整试听，不能断言某一个因素就是全部原因。

下一次正式换声需要一起处理口播稿、术语读法、短语连读、停顿、全片音色一致性与音量。画面术语与实际口播可以不同，但必须建立映射并用真正的口播稿做对齐；不能在替换读法后沿用旧时间轴。调大音量、强行加速或换模型名字都不能代替听感验收。

## Ming TTS 的选择与接法

如果指的是 inclusionAI/蚂蚁的 Ming，纯旁白应选其专门的 [Ming-3.0-tts](https://github.com/inclusionAI/Ming-3.0-tts)，而不是先部署大型多模态对话模型。官方提供 0.5b Dense 与 tiny MoE 两个版本，支持参考音色、音色设计与表达控制；不同任务模式有参数约束。建议先用 0.5b 做本项目同稿试音；这只是部署评估顺序，不是已经证明它的中文听感胜过 Qwen。

官方自带的中文男声“灵楷”可列为试听候选，也可以用官方 SDK 的音色设计/自由表达任务产生符合“专业讲解、男声、普通话自然、句内连贯”的音色。选定后保存为参考，并用同一参考保持整片一致。不要随意混用自由指令、IP 音色和音色设计的参数。

本项目目前接的是 [SGLang-Omni Ming TTS](https://sgl-project.github.io/sglang-omni/cookbook/ming3_tts.html) 的 `/v1/audio/speech`，本次补充其已明确文档化的 `ref_audio`、`ref_text` 和 `seed`，并将参考身份与随机种子纳入缓存。服务端参考文件内容改变时还需更新服务修订号。参考原文和音频不进入导出的配置日志；只记录指纹。

SGLang 该页面的基本示例不等于支持官方 SDK 的全部 VOICE_DESIGN/FREEFORM/IP 参数，本项目不会盲目把这些参数塞进兼容接口。高级音色设计需要单独适配并验证所选运行时。

配置示例（模型 ID 必须与实际服务注册值一致）：

```dotenv
EXPLAINER_MING_URL=http://your-private-tts-server:8000
EXPLAINER_MING_MODEL=inclusionAI/Ming-3.0-tts-0.5b
EXPLAINER_MING_REF_AUDIO=voices/approved-male.wav
EXPLAINER_MING_REF_TEXT=与该参考音频逐字一致的文本
EXPLAINER_MING_SEED=123
EXPLAINER_TTS_REVISION=male-voice-v1
```

参考路径由语音服务读取；不是应用主机的同名路径。选择 Ming 是显式操作；不会自动改成 Edge。Ming 没有提供本项目已验证的词时间戳，正式影片仍需配置真实对齐服务，重新计算字幕、镜头和事件。

建议先用 60–90 秒同稿比较 Edge、可用的 Qwen 和 Ming：普通句、技术术语、长句、停顿与段间衔接都要包含；分别评估自然度、读音、节奏、音色一致和清晰度，再决定整片采用哪个方案。

## 当前验证边界

本环境未配置 Ming 服务、Qwen 权重/服务或本地对齐模型，也没有 GPU CLI。Ming 请求协议与缓存使用明确标记的模拟返回测试；不能将这些测试称为真实模型推理、听感对比或部署验收。新版影片仍是 Edge 音轨。

新封面/结尾是实际渲染的 4K 动态页面；正文按已验证视频指纹复用，并保留原始可编辑工程。四个正文采样帧与源片像素比较 RMS 为 0，包含已知的结束淡出帧。最终 2137 帧、71.233333 秒，完整解码通过。原始正文可编辑源与新增合成工程一并交付。
