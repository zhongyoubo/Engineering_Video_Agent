# Concrete objects, scenes and causal effects

The HDMI review exposed a product gap: the compatibility sample had only generic graph
nodes. Successful encoding, type checking and readable text did not make devices or
mechanisms visible. This update adds a reusable object/action layer to the trusted
renderer and the existing native planning contract.

## Planning and material choice

Plan an explanatory goal, objects, setting, named ports, initial state, action, visible
result, narration anchor and optional quiet interaction cue. The native semantic planner
receives visual_scene_toolkit; the external storyboarding path receives the same guidance.
No keyword classifier or automatic HDMI-to-fixed-template router is introduced.

`Scene.visual_scene` is optional and mutually exclusive with old motion/diagram layouts.
Old boards remain loadable. Select a method by its explanatory purpose: object interaction,
real UI capture, diagram, comparison or custom authored SVG/TSX. The existing native Agent
may freely author unsupported shapes under isolation; the object catalog is not its limit.
This change does not connect an arbitrary text-to-image/video service or claim that every
new subject automatically receives a unique original asset. The explicit model-free
compatibility planner remains a draft arranger; it does not pretend semantic authoring.

## Data protocol

- Objects: eleven vector prototypes (TV, monitor, laptop, console, player, soundbar,
  speaker, remote, phone, server, router), bounded position/size, labels, color, initial
  power, screen content, playback style and ports. Ports have side, normalized position,
  label and connector kind; there are no executable strings, remote URLs or asset paths.
- Connections: two actual object/port references, cable or wireless, and initial connected
  state. Object and connection IDs are distinct. Wireless uses a dashed control channel,
  not a solid physical cable or HDMI connector.
- Actions: reveal, connect, signal, power_on/off, play, sound, press, volume and highlight.
  Each references an actual narration phrase, occurrence/edge/offset and bounded duration.
  Signals distinguish video (picture tiles), audio (wave glyphs), control (amber pulses)
  and data. Direction can reverse, including TV-to-soundbar return audio.
- Events can depend on prior event IDs. Invalid references, cycles, missing phrases and
  conflicting visual representations fail validation. Measured compilation also rejects
  events outside the actual scene budget, prerequisites not yet completed, signals before
  connection, and playback/audio before power-on or after power-off. Failed compilation
  publishes no partial object event list. Draft estimates remain explicitly labeled.

The same measured phrase resolver serves old and new motion. A phrase inside a measured
provider span retains the span boundary; character-level timing is not invented.
Positions use the existing 1920x1080 logical canvas: a 1720px wide stage, object bottoms
within 560px and label room to 650px. Root rasterizes vector/type at 1080p or native 4K.
Actors have persistent power/play/volume state; signals, sound waves and press feedback
are transient frame-driven effects. No wall-clock time, randomness or source evaluation.

## Sound, export and review

Optional original additive-synthesis connect/click/notify WAV cues are versioned under
assets/sfx, with generator and provenance. sound_enabled defaults false; gain is bounded
at .35 (default .18). Asset preparation copies only used allowed presets. Effects are mixed
by the trusted renderers under narration, not generated by the reasoning provider.
`narration.wav` remains speech-only. Foley illustrates an interaction; it is not electrical
HDMI signal sound, measured speaker output or claimed device recording.

Compatibility and native wrapper use the same protected scene-objects.tsx. Native author
code composes ObjectScene; the platform still requires real source authoring/build and
hash-bound preview/review/finish. ObjectSceneSounds, font, narration and captions are
trusted wrapper responsibilities. Do not duplicate Foley in authored components.
Publication thumbnails can show an actual object scene pose; opening/closing object
scenes are not covered by generic wave cards. Local factual/provenance disclosures remain.

Native visual review adds object_fidelity and causal_motion >=4/5 when object scenes are
present, preserving all prior motion/publication/source gates. Continuous preview windows
prefer an observable picture/audio/signal event; a four-second window does not cover every
action. Studio exposes actual object labels, phrase anchors, sound opt-in and timing source.
Editing them clears compiled object timing; saving recompiles against actual audio and
invalidates visual fingerprints. The old diagram selector is disabled for an object scene.

## Verification and limits

scripts/verify_object_scenes.py renders only fixed repository-authored data and a fixed
verified dispatcher in both paths. It checks actual screen changes, decoded videos, quiet
Foley audio and the eleven prototype shapes. Timing is authored draft estimation, not
native inference/TTS. See docs/verification-object-scenes.json. The HDMI revision separately
uses its unchanged real Edge narration and actual WordBoundary timestamps.

Human full watching/listening, real native generation, unknown-object quality, photo/3D
asset generation, detailed material/lighting systems, general camera choreography, real
120Hz/HDR or hardware experiments remain separate acceptance work. These fixtures do not
certify them. The implementation is a composable scene capability, not a finished universal
visual effects or nonlinear editing system.

Actual HDMI revision evidence: docs/verification-hdmi-object-scenes.json (eight scenes,
121.1s, both decoded resolutions, measured narration and encoded-frame inspection).
