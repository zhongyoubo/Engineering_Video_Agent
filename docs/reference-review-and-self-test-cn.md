# 三个参考视频复查与本项目自测

## 判断

**现有工程已经具备制作这类讲解动画的技术基础，但还不能认定能够全自动、稳定地达到三个参考视频的效果。** 本次用项目自己进行了源码导入、分镜编辑、真实配音、TSX 编译与视频渲染，交付项目介绍片及可编辑工程。介绍片采用固定编排，不能冒充一次真实原生模型的端到端自动生成。

此前的无配音九秒固定测试只证明若干图形可以正确渲染；它不能证明脚本质量、自然配音、真实交互、完整叙事或任意工程适配。本次扩大了实际验证范围，同时保留这些区别。

## 三个视频分别借鉴什么

本次复查使用此前提供的三份录屏文件，而非仅依据视频号链接。以下是从画面观察得到的分析；无法从成片确定原作者使用了什么工具，也不将画面中的技术主张直接视为已核实事实。

| 参考素材 | 核心表达 | 关键运动 | 工程实现路径 |
|---|---|---|---|
| `VID_20261116_230851.mp4`，约 143.48 秒 | 代码/提示词、问题清单、工具与人的关系 | 代码扫描、逐项出现、局部强调、关系连线 | React/SVG 代码区、对象列表、扫描进度、节点图；用旁白短语定位事件 |
| `Screenrecorder-2026-11-16-23-01-52-429.mp4`，约 185.81 秒 | 多个观念按章节展开，用视觉隐喻解释投入与积累 | 扇形概览、浅坑与深井、日历、网络、增长曲线 | 扇形/网格布局、深度积累组件、日历与折线专用镜头；对象随叙述改变状态 |
| `Screenrecorder-2026-11-16-22-55-23-749.mp4`，约 361.49 秒 | 模型路由、推理、上下文、记忆、权限与并发等机制 | 分支树、调节控件、任务矩阵、容量与粒子瓶颈 | 带真实状态的控制器、路由图、队列模拟、容量条、权限门；不应只用文字卡代替机制 |

共同特点是暖白底、深青色主体、少量红色强调、章节一致、留白充分，以及一次只增加少量信息。真正需要学习的是“讲到什么，什么对象发生变化”：不是把整页文字放好后统一淡入，也不是简单生成插画。

实现上适合 Remotion + React/SVG：帧驱动、可重复、可编辑，图形和文字可以直接输出 4K。需要浏览器页面时录制真实操作，保留比例；需要代码时显示真实片段并注明静态依据。原作者的具体实现工具未知。

## 本次发现并修正的问题

1. 部分图解会对超出显示容量的元素静默截取；长标签也存在截断/越界风险。现在按图解类型校验数量和长度，原生策划请求同步提供相同约束，并对中心节点、深度说明等采用有边界的换行布局。规则是受支持范围内的约束，不是任意文字的完美排版器。
2. 缺少第二个参考视频里的扇形概览。补充 `layout=fan`，按数量调整卡宽、间距和角度；工程/模板类型、JSON Schema 与工作台入口同步更新。
3. Edge 原先未收集实际词时间戳，正式模式预检又一律要求本地 Whisper 权重。现在请求 WordBoundary、收集实际时间戳，按语速修正，并在时间轴阶段校验文本一致、单调和音轨范围。显式 stable-ts 仍要求本地权重；不会伪造 Whisper 已通过。
4. 模板播放器暂停在第零帧时，内容透明度为零，造成大面积空白。编辑器初始帧改为一秒处，短片则限制到合法帧内；不改变导出影片的时间轴。
5. GitHub CI 原先使用 `ubuntu-latest`，远端已切换到 Playwright 1.56.1 不支持的 Ubuntu 26.04，依赖安装直接失败。本次固定到 Ubuntu 24.04，并开启隐藏验证目录的产物收集。随后又定位到完整 Chromium 已移除旧 Headless 模式，改为由 Remotion 的 ensureBrowser 安装兼容的 Headless Shell。远端状态另行记录，不以本地通过冒充远端通过。

## 本项目实际测试路径

- 从当前仓库受版本控制的文本文件制作源码 ZIP，排除既有生成成片等目录。测试输入包含源码、文档与配置示例，不运行上传的源码。
- 在真实浏览器里选择“模板 + 仅脚本分镜”，上传本项目，选择 4K 和暖色设计；实际解析 **187 个文本文件**，生成 **6 个分镜**。
- 展开内容依据、编辑视觉表达与扇形布局、添加旁白同步事件、另存版本并打开差异。录制的是实际操作；没有把它标为原生模型的结果。
- 介绍片旁白取自已经公开的 README，固定到提交 `8973bcade2f342eda2a082024ff73c4904b722e5`，逐段检查为原文摘录。新配音为 Edge `zh-CN-YunxiNeural`；不发送源码 ZIP、私有输入、日志或凭据。使用实际服务词边界，未调用 Whisper。
- 由固定的 `examples/project-intro/Video.tsx` 编排项目介绍镜头，使用工程骨架、字体、旁白、字幕、实际波形与真实工作台录像。它是仓库作者编排的测试源代码，不放开生产环境在宿主机执行用户/模型代码的限制。
- 对精确当前源代码/属性/素材指纹分别构建、预览和最终渲染，打包检查拒绝旧指纹产物。

工作台素材录制为 1920×1080，在 4K 画布中按比例放大、以 1.25 倍播放；不能把这部分源像素声称为原生 4K。其余文字和图形为帧驱动矢量/React 元素。

## 仍需完成的参考效果验收

先部署一个真实原生 Agent、一个明确选择的配音服务和无凭据的隔离渲染 Worker，再用本项目完整执行策划、写 TSX、构建、预览、修复与交付。随后分别增加三个参考类型的评测样例：代码评审、多观念隐喻、系统机制。每类检查是否真的表达关系和变化，而不只统计卡片数量。

优先补充日历/曲线、分支树、可变参数与权限门等专用表达，以及跨镜头对象延续和完整音画复看。保留真实视听问题清单，修改后重新生成同哈希证据。自然度、断字、口误和最终叙事节奏需要连续试听；当前测量和自动检查不能替代该结论。

不能宣称：已完整复刻参考片、已打通真实模型的任意源码一键生成、已经部署 Qwen/Whisper、全部素材为原生 4K、人工试听通过。

## 最终实测结果

- 介绍片：**64.235 秒，3840×2160，30fps，1927 帧**，H.264/AAC，完整解码通过。
- 新配音：Edge 云希，7 段实际音轨共 57.858669 秒，132 个实测词边界；为完整旁白与结尾保留停留时间，未截断语音。
- 最终成片音频：综合响度 **−17.41 LUFS**，真峰值 **−4.46 dBTP**，响度范围 6.9 LU。没有把幅度测量称为人工听感认证。
- 预览：21 张 4K 关键帧、7 个连续片段及其采样图；检查并修复录制缩放黑边和编辑器空白首帧。
- 整片全黑检查：阈值 0.1、持续至少 0.2 秒的全黑片段为 0；这项检查不能排除所有局部遮挡或叙事问题。
- 源码导入：187 个文本文件，6 个兼容模式分镜，实际完成依据展开、动效编辑、版本保存与比较。
- 后端 **95 项测试通过**；浏览器 **6 项通过**，包括暖色 4K、扇形布局跨版本保存和暂停预览可见性；类型检查、生产构建、格式检查通过。
- 远端代码提交 `a36532f1ba94bcd735bd5052bd3330bec41c08de` 的 [GitHub CI](https://github.com/zhongyoubo/Engineering_Video_Agent/actions/runs/43916631812) 已通过，包含固定 4K 视觉夹具和实际 MCP SDK/API 验证。后续策划约束与打包测量修改另按最新提交复验；不把旧 CI 自动套用于新代码。
- 助手进行了画面采样审查；没有声称人类完整观看/试听通过，亦未执行真实原生模型或隔离 Worker 的集成验收。

可编辑交付包含独立 Remotion 工程、所需字体/音轨/工作台素材、脚本、SRT、检验 JSON 与输入证据。工程和素材均采用本次实际渲染的版本；生产任务的旧哈希审查失效规则保持不变。
